GravitationalWaveBayes.NUTSCore.NUTSBounds — Type
NUTSBounds{T}(lo::AbstractVector{T}, hi::AbstractVector{T}; periodic=falses(length(lo)))

Per-parameter box constraints enforced DURING leapfrog integration (see the docstring of NUTSConfig for why a hard -Inf wall alone is correctness-safe but wasteful).

lo[i]/hi[i] are parameter i's bounds; use T(-Inf)/T(Inf) (either or both) to leave a row unconstrained by this mechanism (it falls back to whatever the caller's logp_and_grad! itself does – e.g. this package's own -Inf-prior fallback in BatchedNUTS.jl, which stays in place regardless, see that file's _log_prior).

periodic[i]: true for an angular coordinate whose lo/hi are identified (e.g. a phase or right-ascension on [0, 2*pi)) – handled by WRAPPING the position modulo hi-lo with the momentum left untouched, not by reflecting. This is the standard treatment of a periodic/angular HMC coordinate: lo and hi are the SAME point on the underlying circle, so there is no physical wall there for the trajectory to bounce off – wrapping is just using the coordinate's own periodicity (working on its universal cover), and is trivially measure-preserving and reversible since it does not touch the momentum at all. Reflecting a periodic coordinate instead would be wrong: it would treat two identified points as a hard wall, folding the sampled distribution over on itself. false (default) uses REFLECTION (see nuts_draw!'s leapfrog step): the standard technique for a genuine hard box constraint (Neal, R.M. 2011, "MCMC Using Hamiltonian Dynamics", in the Handbook of Markov Chain Monte Carlo (Brooks, Gelman, Jones & Meng, eds.), Chapman & Hall/CRC – the "bounce" construction for a constrained parameter: when a leapfrog step would carry a coordinate past a boundary, reflect the coordinate back into the domain and negate the momentum component normal to that boundary, i.e. treat the boundary as an idealized elastic wall). See this module's comment above _reflect_component for why this exactly preserves the Hamiltonian and the leapfrog map's reversibility/volume-preservation (the two properties NUTS's correctness proof needs), and test/test_nuts_core_bounds.jl for an empirical check (a flat-target "particle in a box" recovers a uniform stationary distribution, and a truncated-Gaussian target recovers the correct truncated-normal moments) rather than relying on the argument alone.

GravitationalWaveBayes.NUTSCore.NUTSConfig — Type
NUTSConfig{T}(; max_treedepth=10, target_accept=T(0.8), max_delta_energy=T(1000), nwarmup=500,
             bounds=nothing, adapt_mass=false)

Tuning parameters for nuts_sample!.

  • max_treedepth: cap on the doubling depth; a trajectory grows to at most 2^(max_treedepth+1)-1 leapfrog steps.
  • target_accept: dual-averaging target acceptance statistic (delta in Hoffman & Gelman 2014 Algorithm 6).
  • max_delta_energy: divergence threshold on |H - H0|.
  • nwarmup: number of draws (out of nsteps passed to nuts_sample!) during which the per-walker step size is adapted via dual averaging; the remaining draws use the frozen, averaged step size.
  • bounds: nothing (default, no change from pre-Phase-5 behavior) or a NUTSBounds enforcing per-parameter box constraints by reflection/wrapping during leapfrog integration (see NUTSBounds's docstring). A caller whose logp_and_grad! already returns -Inf outside some region (e.g. this package's BatchedNUTS._log_prior) does not NEED bounds for correctness – NUTS already handles a -Inf/non-finite Hamiltonian as a divergence and discards the offending subtree (see nuts_draw!'s subtree_valid handling) – but relying on that alone means every trajectory that would cross a tight bound gets truncated there instead of continuing to explore, which is wasteful when the bound is tight relative to the typical step size. Passing bounds lets the trajectory keep growing past what would otherwise be a dead end.
  • adapt_mass (default false, exact pre-existing unit-mass behavior): adapt a DIAGONAL inverse mass matrix (one variance-like scale per parameter, shared by all walkers) during warmup, using Stan's windowed schedule – see nuts_sample! and _mass_adaptation_windows. Needs nwarmup >= 20; with fewer warmup draws it is a silent no-op (Stan does the same).
  • dense_mass (default false; needs adapt_mass=true): adapt a DENSE (full-covariance) inverse mass matrix instead of a diagonal one – see DenseMetric. Needed whenever the target has strong parameter correlations (every GW posterior does: chirp mass / mass ratio / spin / t_c / phase), because a diagonal metric can only rescale the axes and the step size is then still limited by the narrowest correlated direction. Not combinable with metric_rank (parallel tempering).
  • hessian_init (default false; needs dense_mass=true): before warmup, bootstrap the dense metric from a finite-difference Hessian of the supplied gradient (see _hessian_metric), evaluated at every walker and pooled. Fixes the circular failure of purely sample-based adaptation from a badly-scaled start: if the initial step size is tiny relative to the posterior, the walkers barely move, the window variance measures that jitter, and the metric learns the scale of the failure rather than of the posterior (seen on GW150914: 300 draws, no mixing). Costs 2*nparams batched gradient evaluations. hessian_rel_step (default 1e-6) is the central-difference step as a fraction of each parameter's box width (bounds), or of max(1, |x_i|) for an unbounded row.
  • mass_init_buffer, mass_base_window, mass_term_buffer (defaults 75, 25, 50, Stan's schedule): the step-size-only initial buffer, the first slow window's length (later ones double) and the step-size-only terminal buffer, in warmup draws. Only used when adapt_mass=true; if they do not fit in nwarmup the schedule falls back to a 15%/75%/10% split. With hessian_init the initial buffer can be short (the metric is already sensible), so set it small to spend warmup on slow windows instead.
  • cull_logp_gap (default 0 = off; needs adapt_mass=true, not for metric_rank): at the end of every slow window during WARMUP, any walker whose logp is more than this far below the best walker's is treated as stuck in a secondary local mode (HMC cannot hop between modes): it is left out of that window's metric estimate and re-seeded from a randomly chosen good walker (position, logp, step size). Never runs after warmup, so the sampled chain is untouched. On real IMRPhenomXAS/H1 data half the walkers, started at 2% of the box span around the base point, settled in modes ~165 logp units below the true one, for the diagonal and dense metric alike.
  • quorum_frac (default 0 = off, exact pre-existing behavior): each tree-doubling round normally runs for EVERY walker until any(active) becomes false, i.e. until the LAST walker's trajectory stops growing – one pathological walker (e.g. sitting on a stiff, poorly-whitened ridge) forces every other walker's tree to keep doubling too, since the batch advances one depth level at a time together (on real data, 100% of post-warmup draws hit max_treedepth). With quorum_frac > 0, once fewer than ceil(quorum_frac * nwalkers) walkers remain active (with a floor of 1, so quorum_frac=0 reproduces any(active) exactly), the round stops early and every still-active walker is administratively truncated at its current depth – same handling as exhausting max_treedepth, just triggered by straggler count instead of depth. Surfaced per-walker as stats.quorum_forced (distinct from diverged: this is a scheduling cutoff, not a numerical failure). E.g. quorum_frac=0.75 with 16 walkers stops once fewer than 12 remain active.
  • step_size_max_change (default 8, needs >= 1): bounds how far a single MID-WARMUP RESTART of _find_reasonable_step_size! (Stan's doubling/halving search from a single test leapfrog, re-run every time a metric-adaptation window ends and installs a new metric) may move step_size from its value going in, in EITHER direction. A metric-driven restart's single test leapfrog can give an unlucky accept/reject read for several doublings in a row, letting the search overshoot 30-45x before its own crossing criterion fires – dual averaging then spends many expensive draws (each a full waveform-gradient batch) correcting back down, with a spike in divergence rate along the way. 8 bounds any one restart to at most 3 doublings/halvings from where it started; sacrifices some of the search's ability to jump straight to a very different step size in one restart, but that's the whole point – multiple smaller corrections (each still gated by dual averaging afterward) are safer than one large jump from a single noisy leapfrog. Deliberately does NOT apply to the INITIAL hessian_init bootstrap call (before any draws): that call's whole point is to climb from whatever step_size0 the caller supplied, which may legitimately be many orders of magnitude off (see "step-size heuristic lands near the right scale from either side" in test_nuts_core_dense_mass.jl) – capping it there would defeat it, not hardened it. Only the mid-warmup restart's incoming step size is dual-averaging-tuned already, so a large jump there is the anomaly this option guards against, not the intended behavior.
  • mass_blocks (default nothing = full dense; needs dense_mass=true): restrict the adapted DENSE metric to a block-diagonal structure, e.g. [[1,2,6,7], [3,4]] for a GW posterior's mc/q/t_c/phase ridge kept separate from chi1/chi2 – see DenseMetric's own comment for why this needs no new sampling/kinetic/drift/reflection code: a block-diagonal SPD matrix's Cholesky factor is ITSELF block-diagonal, so DenseMetric's existing machinery already decouples correctly once the matrix it's built from has no cross-block entries. mass_blocks only changes WHAT gets estimated – every Minv this module estimates (Hessian bootstrap, window sample covariance) is masked to zero cross-block entries (_block_mask!) before becoming a DenseMetric, right before the one point that matters: masking a symmetric positive definite matrix down to its block-diagonal restriction is ALWAYS still positive definite (each diagonal block is a principal submatrix of a PD matrix, hence PD itself), so this never introduces a new PosDefException the unmasked estimate wouldn't already have risked. Indices not mentioned in any block are treated as their own independent singleton block (decoupled from everything, including each other) – the same as a diagonal metric for that one parameter. Motivated by a real-data finding: full dense over 11 params from only 16 walkers is data-starved (Rhat up to 228 for t_c) as well as curvature-limited; restricting to the correlations that actually matter needs fewer entries to estimate from the same data.

GravitationalWaveBayes.NUTSCore.PTLadderState — Type
PTLadderState{T}(ntemps; T=Float64, beta_min=T(0.05), backend=KernelAbstractions.CPU())

Bookkeeping for a geometric temperature ladder over ntemps lanes (one NUTS walker per temperature – see BatchedNUTS.batched_pt_nuts!'s docstring for why ntemps == nwalkers is required there, unlike batched_nuts!'s ordinary independent-walkers-all-at-beta=1 design).

beta_ladder[k] = beta_min^((k-1)/(ntemps-1)) for k=1:ntemps, so beta_ladder[1] == 1 (the untempered target posterior, "cold") descending to beta_ladder[ntemps] == beta_min ("hot", flattened) – the standard geometric PT spacing. Kept as a plain host Vector{T} regardless of backend: it is fixed reference data, read only for diagnostics/driver bookkeeping (e.g. "what beta does rank 1 correspond to"), never touched inside _pt_swap_kernel! itself (the kernel only ever reads/writes betas/lane_of_rank/rank_of_lane, from which the assigned beta is always recoverable as betas[lane]).

betas[w]: lane w's CURRENTLY assigned temperature (mutated by pt_swap!) – this is the array BatchedNUTS.gw_logp_and_grad's beta keyword should be given (by reference, so swaps take effect on the very next likelihood evaluation with no closure rebuild needed).

lane_of_rank[k]/rank_of_lane[w]: mutually inverse permutations (lane_of_rank[rank_of_lane[w]] == w) tracking which lane currently holds which ladder rank, maintained incrementally by pt_swap! rather than re-sorted every round – lane_of_rank[1] is always the lane currently running the beta=1 ("cold", target-posterior) chain, the one a caller should record for actual posterior inference (see BatchedNUTS.batched_pt_nuts!'s cold_chain return value).

betas/lane_of_rank/rank_of_lane all live on backend (default KernelAbstractions.CPU()); naccept/nattempt (length ntemps-1, one entry per adjacent ladder pair, indexed by the pair's lower rank) are always plain host Vector{Int} diagnostics, updated from the kernel's tiny accepted output after each round – naccept[k] / nattempt[k] is that pair's running swap acceptance rate.

parity alternates 0/1 each pt_swap! call: an even/odd adjacent-pairing schedule (ranks (1,2),(3,4),... on parity=0, (2,3),(4,5),... on parity=1) so every adjacent pair eventually gets proposed, not just one fixed pairing forever.

GravitationalWaveBayes.NUTSCore.nuts_sample! — Method
nuts_sample!(positions, logp_and_grad!; nsteps, step_size0, cfg=NUTSConfig{T}(...),
             rng=Random.default_rng(), record=false, warmup_logp_and_grad!=logp_and_grad!)

Run nsteps NUTS draws in place on positions (nparams x nwalkers), using dual-averaging step-size adaptation for the first cfg.nwarmup draws and a frozen (dual-averaging-converged) step size thereafter.

logp_and_grad! must conform to the module-level interface documented above. Returns a NamedTuple (positions, logp, step_size, chain, inv_mass); chain is nothing unless record=true, in which case it is a (nparams, nwalkers, nsteps) array of every draw's positions (used by the Gaussian-recovery test to pool post-warmup samples across both steps and walkers).

warmup_logp_and_grad! (defaults to logp_and_grad! itself, i.e. a no-op – exactly the pre-existing single-closure-for-the-whole-chain behavior): an optional SEPARATE callable, same interface, used only for draws it <= cfg.nwarmup; logp_and_grad! is used for every draw after that, same as always. This exists for callers whose main (post-warmup) kernel is unsafe to use during warmup itself – e.g. BatchedNUTS's relative-binning kernel for SEOBNRv5AlignedSpinF2, where a real NUTS chain's UNADAPTED warmup step size was measured to transiently breach the binned kernel's own aliasing-safety ceiling before dual-averaging shrinks the step size, even though the CONVERGED post-warmup step size stays deeply inside the safe region. Passing the dense (always-safe) kernel as warmup_logp_and_grad! and the binned (fast, but only post-warmup-safe) kernel as the main logp_and_grad! makes that pattern directly expressible: dense during warmup, binned once the step size has converged. When warmup_logp_and_grad! is left at its default, it <= cfg.nwarmup selects the SAME closure either way, so this keyword changes nothing about the default call path (confirmed by test/test_nuts_core_bounds.jl's own switch-mechanism testset, including a bitwise-identical-trajectory check at a fixed seed).

callback (default nothing): an optional (it, positions, logp, step_size, stats) -> nothing called once at the end of every draw it (after that draw's step-size update, if any), given this module's own read-only view of the just-completed draw. Exists so a caller can hook in per-draw side effects (parallel-tempering swap rounds via pt_swap! being the motivating case – see BatchedNUTS.batched_pt_nuts!) WITHOUT NUTSCore itself knowing anything about what the callback does – kept generic/GW-agnostic per this module's own design (see the module docstring above), the same reason logp_and_grad! itself is a caller-supplied closure rather than something this module constructs. positions is passed as the SAME array nuts_sample! mutates in place (not a copy), so a callback that mutates it (e.g. pt_swap! mutating a PTLadderState's betas/lane_of_rank that a tempered logp_and_grad! closure captured by reference) takes effect starting with the NEXT draw, exactly like updating logp_and_grad!'s other captured state would.

stats is the NamedTuple nuts_draw! returns for this draw: (; accept_stat, depth, n_leapfrog, diverged), each field a length-nwalkers vector – accept_stat: the Metropolis-style acceptance statistic dual averaging targets; depth: the tree-doubling depth this walker's trajectory reached before terminating (U-turn, divergence, or exhausting cfg.max_treedepth); n_leapfrog: total leapfrog integrator calls (gradient evaluations) this walker's draw made; diverged: whether a non-finite or max_delta_energy-exceeding Hamiltonian was hit anywhere in this draw's tree, as opposed to ordinary U-turn termination. Near-zero overhead (these are scalars nuts_draw! already computes internally; no new gradient/likelihood evaluations). Answers directly, instead of by inference from draw wall-clock timing, questions like "is this run still maxing out max_treedepth every draw post-warmup" (depth at or near cfg.max_treedepth well past cfg.nwarmup) or "did this draw diverge" (any(diverged)).

nothing (default) preserves the exact pre-existing behavior with zero overhead.

Diagonal mass matrix. With cfg.adapt_mass=true and cfg.nwarmup >= 20, warmup follows Stan's windowed schedule (_mass_adaptation_windows): a step-size-only initial buffer, slow windows of doubling length, a step-size-only terminal buffer. At the end of each slow window the inverse mass matrix (diagonal, one entry per parameter, SHARED by all walkers) is set to the pooled within-walker sample variance of that window's positions, and dual averaging restarts from the current step size (mu = log(10*step)). Momentum is drawn as N(0, M), kinetic energy is 0.5 r'M^-1 r, the position drift is eps*M^-1 r, and the U-turn criterion uses M^-1 r (Betancourt 2017) – so the target is unchanged; only efficiency is. Differences from Stan: variance is NOT shrunk toward 1e-3 (that constant assumes O(1) parameters; the GW sampled space spans many decades), and no find-reasonable-step-size heuristic runs after a metric update (dual averaging recovers within a few draws; validated in test/test_nuts_core_mass_matrix.jl). By default the metric is shared across walkers, which is wrong for parallel tempering (each lane targets a different tempered density, and the beta LABEL moves between lanes on a swap – see metric_rank).

metric_rank (default nothing; PT only): a length-nwalkers vector, read by reference every draw, giving each walker's current temperature rank – pass pt.rank_of_lane, a permutation of 1:nwalkers. The metric is then attached to the RANK, not the lane: inv_mass becomes an (nparams, nranks) matrix, each draw gathers the columns for the walkers' current ranks, and adaptation accumulates rank r's own stream (whichever lane held rank r on each draw) with NO pooling across ranks – hot ranks legitimately learn broader scales than the cold one. Correct because the rank is part of the extended (position, label) state and the metric is a fixed function of it within a draw (and frozen after warmup). A matrix inv_mass0 requires metric_rank.

inv_mass0 (default nothing = identity metric, the exact old code path – bit-for-bit identical chains): initial inverse-mass-matrix diagonal, length nparams (or (nparams, nranks) with metric_rank). Together with the returned inv_mass this lets a caller carry an adapted metric from a warmup call into a later nwarmup=0 sampling call (see scripts/run_from_config.jl's two-phase relative-binning runs). The returned NamedTuple's inv_mass is the metric in effect at the end (ones if none was ever set).

GravitationalWaveBayes.NUTSCore.pt_swap! — Method
pt_swap!(pt::PTLadderState{T}, ll::AbstractVector{T}, rng::AbstractRNG) where {T}

One parallel-tempering swap round: proposes an accept/reject exchange of the beta LABEL (not the physical position) between every adjacent-in-rank pair at pt's current parity, using each lane's own raw (untempered) log-likelihood ll[w] at its own current position (the caller must compute this immediately before calling, e.g. via BatchedNUTS._raw_loglikelihood! – it is NOT the tempered logp NUTSCore.nuts_sample! tracks, and NOT recoverable from that, since the tempered value already has beta baked in and the log-prior added). Mutates pt.betas, pt.lane_of_rank, pt.rank_of_lane in place (via _pt_swap_kernel!, see this section's module comment for the backend-portability note), updates pt.naccept/pt.nattempt, flips pt.parity for the next round, and returns pt.

ll must live on the same backend as pt.betas (both derived from KernelAbstractions.get_backend internally). A no-op (returns pt unchanged, no swap possible) when ntemps < 2.

GravitationalWaveBayes.NUTSCore.smc_sample — Method
smc_sample(positions0, loglik!, logp_and_grad!, betas; cfg, rng, kwargs...) -> NamedTuple

Adaptive tempered SMC sampler with batched NUTS mutations (see the comment block at the top of SMCCore.jl). positions0 is (nparams, N): N exact prior draws. betas is the length-N vector the tempered logp_and_grad! closure reads; this function overwrites it with the current stage's beta before every mutation.

Keywords:

  • cfg::NUTSConfig: tree depth, bounds, quorum; its nwarmup/adapt_mass are ignored (the metric and step size are set by the population), mass_blocks restricts the population metric.
  • moves (:nuts): the mutation kernel. :rw = gradient-free adaptive random-walk Metropolis with the population covariance as the proposal shape (for models whose gradient costs many likelihoods); it only calls loglik! (one batched call per draw over all particles) and logprior!, and logp_and_grad! may be nothing. Needs logprior!(lp, positions): the log prior per column, -Inf outside its support (no likelihood is evaluated there). Periodic rows of cfg.bounds are wrapped. The scale starts at rw_scale0 (2.38/sqrt(d) whitened) and is tuned after every ladder draw toward rw_target_accept (0.234); max_mutate defaults to 1000 draws and disp_target to 1.2 (at 1.0 a correlated d = 6 Gaussian's log Z came out 0.25 low on average over 8 seeds, at 1.2 and 1.35 unbiased within 0.06 / 0.07; independent draws give sqrt(2)). The recorded beta = 1 phase keeps one state every rw_thin draws (default: the last ladder stage's draw count). A fraction rw_de (0.5) of the proposals are differential-evolution steps x + s/sqrt(2) (xa - xb) (+ 1% jitter) along differences of the stage's starting population, the full difference (a mode jump) with probability rw_de_jump (0.1); rw_de = 0 = Gaussian steps only. Not combinable with independence, online_proposal or block_move.
  • target_cess (0.5): conditional-ESS fraction that sets each beta increment.
  • final_ess (nothing = off): a stage that would stop short of beta = 1 (in a hybrid only from the first NUTS stage on) goes to beta = 1 instead when the incremental weights' ESS / N there is >= final_ess. Only useful below target_cess (at or above it the target alone already decides).
  • dense (true): block-dense population metric; false = diagonal. mass_blocks (default cfg.mass_blocks) masks cross-block entries, as in NUTSConfig.
  • min_mutate/max_mutate (2/20): NUTS draws per stage; a stage stops once EVERY row's typical displacement from the post-resampling positions reaches disp_target (1.0) population sds, so resampled duplicates have separated in the slowest direction, not just in unconstrained ones. move_stat (:median) measures it as sqrt(2) median |displacement| / median distance between randomly paired particles (robust to particles jumping between modes, to minor modes and to flat rows); :rms = RMS displacement / weighted population sd (the earlier rule).
  • nfinal (20): draws at beta = 1 after the ladder, all recorded (chain, (nparams, N, nfinal)).
  • final_max_treedepth (nothing = cfg.max_treedepth): the NUTS tree-depth cap of the recorded beta = 1 phase only (every move stays exact; a shallower cap trades autocorrelation between recorded draws for gradients per draw).
  • step_size0 (0.5): initial step size in whitened units (refined once by the step-size heuristic), then tuned after every ladder draw toward cfg.target_accept from the population's mean acceptance statistic; frozen during the recorded beta = 1 phase.
  • reference (default nothing = anneal from the prior): a NamedTuple (; logq_and_grad!, logprior_and_grad!), each (lp, grad, positions) -> nothing filling a log-density and its gradient. positions0 are then draws from the NORMALIZED reference q0 and the path is q0^(1-beta) (prior L)^beta; logZ is still the evidence relative to the prior (exact as long as q0 is normalized on the sampled support and covers the posterior – use a defensive mixture with the prior). The returned ll is then logL + logprior - logq0. An optional sample(rng, n) field enables independence.
  • independence (false): after every NUTS draw, also propose each particle afresh from q0 and accept by independence Metropolis-Hastings (exact for pi_beta; a global move across modes/ridges).
  • online_proposal (default nothing): a function (pool, weights) -> (; sample, logq_and_grad!) (or nothing to keep the current proposal). After every ladder stage it is called with that stage's mutation states ((nparams, m), thinned to online_pool_max) and the returned normalized density is used for independence-MH moves throughout the NEXT stage (and the final phase). The annealing path is unchanged (prior, or reference); only the global proposal adapts, and each stage's proposal is fixed before its moves, so every move is exact for its pibeta. This is the training-free analogue of flowMC's on-the-fly flow (e.g. a local KDE of the pool plus a prior component), removing the need for a reference from an earlier run. `onlinenuts = false`: a hybrid builds and uses it in its RW stages only (a hybrid's NUTS stages then make no independence moves and fit no proposal).
  • persistent (false): persistent sampling (Karamanis et al. 2025). Every stage's post-mutation population is kept; each new stage resamples from the WHOLE pool with multiple-importance weights against the equal mixture of the earlier targets, and log Z uses the same weights. Particles lost to an earlier resampling can return, which stabilizes minor-mode weights at no extra likelihood cost (the pool's log-ratios are stored). The beta schedule still uses the current population's CESS.
  • independence_tries (1): independence / online-proposal MH steps per NUTS draw (each one exact; cheap with logprior!, so several per draw multiply the global moves at little cost).
  • ind_llk (nothing): a log-likelihood ind_llk(ll, X) for independence_tries * N columns at once (prior or reference path with logprior! only). All of a draw's independence proposals are then drawn and evaluated in one batch (one wide device call instead of independence_tries narrow ones) and applied as the same sequence of MH steps: the proposals do not depend on the current state, so this is the same chain.
  • de_tries (0), de_jump (0.1): differential-evolution Metropolis steps per NUTS draw (needs logprior!, prior path): x' = x + g (xa - xb) + 1% jitter with a random pair of the stage's starting population, g = 2.38/sqrt(2d) (x U(0.8, 1.2)) or 1 with probability de_jump; one likelihood call each. They follow curved ridges and jump between modes, where NUTS with one population metric needs tiny steps.
  • logprior! with moves = :nuts: optional; on the prior path it makes independence / online-proposal moves evaluate beta * loglik! + logprior! (one likelihood call) instead of logp_and_grad! (must be the same density).
  • rw_moves ((), moves = :rw only): extra proposals after every random-walk draw, each a function move!(xp, positions, rng) filling xp ((nparams, N)) with one proposal per particle; each must be symmetric with respect to Lebesgue measure on the sampled coordinates (e.g. a measure-preserving map with a symmetrically drawn parameter: a rotation of the sky about a detector baseline by a random angle), so plain MH applies. One likelihood call each; acceptance reported as move_accept.
  • mode_jumps (false): learned mode-jumping moves (_mode_jump_learn!, _mode_jump_tries!). After every ladder stage at beta >= mode_jump_learn_beta (0) the population is clustered by k-means into mode_jump_k (10) cells on the mode_jump_rows (nothing = all rows; standardized, periodic rows of cfg.bounds as (cos, sin)), and the mean difference of every pair of cells holding >= max(10, mode_jump_min_cell (0.01) N) particles joins a growing set of jump vectors (never dropped). After every draw of every kernel (RW, NUTS, the recorded phase) each particle then makes mode_jump_tries (12) MH steps x -> x + s delta on those rows, delta uniform over the set as it stood at the stage's start, |s| ~ U(mode_jump_scale...) ((0.2, 0.7)) with a random sign: symmetric, unit Jacobian, plain MH on the stage density. Carries weight between a bulk and a minor mode that NUTS / RW cannot cross, and refills a minor mode that tempering resampling drained. Needs logprior!. The tries are evaluated in rounds of up to mode_jump_batch (1) per particle, one mode_jump_llk call (default loglik!; it must accept mode_jump_batch * N columns; prior path only when > 1) per round (the same chain as sequential tries; a wide device call amortizes latency). Acceptance mode_jump_accept, set size mode_jumps, evaluated columns mode_jump_evals (not in n_loglik). mode_jump_learn (:kmeans) picks the vector source: :tails (_mode_jump_tails!) instead appends, for every tail quantity in mode_jump_tails (functions q(X) -> values, one per particle; nothing = every non-periodic jump row) plus mode_jump_tail_pcs leading principal components (default 3 without mode_jump_tails, else 0), and every fraction p in mode_jump_tail_frac ((0.02, 0.05)), mean(tail) - mean(rest) on the jump rows for the lower and the upper p-tail (>= mode_jump_tail_min (8) particles); :both appends both kinds. The callback's mode_jump_cells then counts the tail quantities used. Applying the jumps is the same either way.
  • nuts_beta (nothing; moves = :rw only): a hybrid – from the first stage at beta >= nuts_beta (and in the recorded beta = 1 phase) mutate with NUTS (logp_and_grad! required, with logprior! the same density), whose whitened step size is set once at the switch (Stan's heuristic) and tuned as in moves = :nuts; at most nuts_max_mutate (20) draws per stage. Random walk finds the signal cheaply while the population is prior-like; NUTS follows the curved posterior manifolds (e.g. mass-spin) once it has. rw_moves keep running after every NUTS draw (prior path).
  • metric_core (nothing): estimate each stage's metric (NUTS mass matrix / RW proposal shape) from only the fraction metric_core of particles with the highest log-likelihood (_metric_weights): robust to prior-like stragglers while the population hands over to a narrow mode. Any fixed metric keeps the moves exact.
  • hessian_metric (0): fold the local curvature into each stage's metric, Minv = (Sigma^-1 + Hbar)^-1 with Hbar the negative Hessian of the tempered target averaged over up to hessian_metric distinct top-logL particles (one batched logp_and_grad! call per stage; needs logp_and_grad!, also shapes the RW proposals of a hybrid). For targets far thinner locally than the population in a few directions (_hessian_metric).
  • local_kernel (:nuts): the gradient kernel of moves = :nuts and of a hybrid's NUTS stages. :mala = mala_steps (10) preconditioned MALA steps per draw (flowMC's local sampler; one gradient each), step size tuned toward mala_target_accept (0.574).
  • latent_nuts (false): run the gradient kernel in the latent space of the stage's online proposal (NeuTra): the proposal must provide to_latent(X) -> Z and from_latent(Z) -> (X, ldj, pull) (as the flow proposals do; stages whose proposal does not fall back to x space). The kernel targets pi(T(z)) |det dT/dz| with the population metric of the particles' latent coordinates and its own step size (_latent_lpg).
  • block_move (default nothing): a function (positions, betas, metric, rng) -> n_evals called after every NUTS draw; it must leave each particle's pibeta = prior L^beta invariant (e.g. NUTS on a parameter block at fixed other rows – Metropolis-within-Gibbs) and returns the number of (cheap) evaluations it made, reported as `blockevals. Prior path only (noreference`).
  • callback(stage, info): optional per-stage hook for progress output (info.positions, info.ll: the current population, not copies).

Returns (; positions, ll, logp, logZ, beta_schedule, chain, nstages, n_leapfrog, n_loglik, step_size, metric, accept, ancestors_unique, mode_jump_accept, mode_jumps, mode_jump_evals, ...): logZ is the log-evidence estimate (normalized to the prior), n_leapfrog the total gradient evaluations summed over particles, n_loglik the untempered log-likelihood evaluations (step_size is the RW scale for moves = :rw), ancestors_unique how many distinct initial prior draws survive in the final population (a mode-collapse diagnostic).

GravitationalWaveBayes.BatchedNUTS.batched_nuts! — Method
batched_nuts!(state::PEState{T,A,V}, data::LikelihoodData, cfg::PEConfig{T};
              nwarmup=max(cfg.nsteps ÷ 2, 1), target_accept=T(0.8), max_treedepth=10,
              rng=Random.default_rng(), model=IMRPhenomD(), relative_binning=nothing)

Run cfg.nsteps batched NUTS draws over every walker in state, sampling the log-POSTERIOR surface defined by data/cfg/model plus the uniform-bounds prior (see _log_prior) – state.positions holds the 11-row SAMPLED convention (mc, q, chi1, chi2, dL, t_c, phase, ra, sin_dec, cos_theta_jn, psi) documented above _reparam_to_physical!, not physical component masses/angles.

state.positions is updated in place to the final draw; state.logp is updated to match. state.energy is intentionally left untouched: unlike the old single-leapfrog-step implementation, NUTS resamples momentum fresh at the start of every draw and discards it once the trajectory's multinomial sample is chosen, so there is no single leftover "energy" value that means anything once a draw completes.

relative_binning: forwarded to gw_logp_and_grad unchanged – nothing (default) uses the full-grid likelihood every step; a RelativeBinning.RelativeBinningSetup uses the sparse bin-edge approximation instead. See RelativeBinning.build_relative_binning for how to build one (needs a reference parameter set and data; a natural choice is state's own starting position, converted to physical (m1,m2,chi1,chi2) via _mc_q_to_m1_m2, before this call runs).

enforce_bounds (default true): whether to pass a NUTSCore.NUTSBounds (built by _sampled_space_bounds from this file's own _..._PRIOR_BOUNDS constants – the exact bounds _log_prior already enforces) so NUTSCore's leapfrog integration reflects/wraps at the sampled-space boundaries instead of relying solely on _log_prior's -Inf fallback to reject a trajectory that crosses one (see _sampled_space_bounds's comment for the reflect-vs-wrap split and its one known gap, IMRPhenomXP's joint spin-norm constraint). _log_prior's -Inf fallback remains active regardless of this flag – it is the correctness backstop, not an alternative; enforce_bounds=false recovers the exact pre-Phase-5 behavior (useful for A/B comparison or if a future caller needs the raw logp_and_grad! unmodified).

dense_warmup (default false): when true (and relative_binning !== nothing), runs WARMUP draws (it <= nwarmup) against the dense (relative_binning=nothing) kernel and only switches to the requested relative_binning kernel once step_size has converged, via NUTSCore.nuts_sample!'s warmup_logp_and_grad! keyword. Exists because a real NUTS chain's UNADAPTED warmup step size can transiently push logp_and_grad! evaluations into a binned kernel's own aliasing-unsafe region even when the CONVERGED post-warmup step size stays deeply safe there – see NUTSCore.nuts_sample!'s own warmup_logp_and_grad! docstring. Throws ArgumentError if dense_warmup=true is passed with relative_binning === nothing (already dense throughout; the flag would be a silent no-op otherwise, which is more likely a caller mistake than an intentional call). false (default) is the exact pre-existing single-kernel behavior for the whole chain, unchanged.

adapt_mass (default false): forwarded to NUTSConfig – adapts a diagonal (per-sampled- parameter) inverse mass matrix during warmup (Stan's windowed schedule), so a stiff direction (e.g. phase/t_c) no longer forces one tiny global step size on every other parameter. false is the exact pre-existing unit-mass behavior. Needs nwarmup >= 20. The adapted metric itself is not returned by this function (it returns state); call NUTSCore.nuts_sample! directly if you need result.inv_mass.

Note on the PEState{T,A,V} type parameters: this signature deliberately spells out the bound A<:AbstractMatrix{T} (mirroring the struct's own declaration in Types.jl) rather than writing PEState{T,AbstractMatrix{T}}, which would pin the type parameter A to the literal type AbstractMatrix{T} itself (Julia struct type parameters are invariant) and never match a concrete instance like PEState{Float64,Matrix{Float64}}.

GravitationalWaveBayes.BatchedNUTS.batched_pt_nuts! — Method
batched_pt_nuts!(state::PEState{T,A,V}, data::DetectorData, cfg::PEConfig{T};
                 ntemps=size(state.positions,2), beta_min=0.05, swap_interval=5,
                 nwarmup=max(cfg.nsteps÷2,1), target_accept=T(0.8), max_treedepth=10,
                 rng=Random.default_rng(), model=IMRPhenomD(), relative_binning=nothing,
                 enforce_bounds=true, pt_backend=KernelAbstractions.CPU(), adapt_mass=false)
                 -> (state, pt::PTLadderState, cold_chain)

Parallel-tempered batched NUTS. Unlike batched_nuts! (every lane an independent walker sampling the SAME beta=1 posterior), each lane here runs an independent NUTS chain at its OWN currently-assigned temperature (log_L_tempered = beta * log_L, log-prior left untempered) – state.positions must therefore have exactly ntemps columns, one lane per rung of the ladder (ntemps == nwalkers is asserted, matching NUTSCore's "each walker/temperature is already an independent trajectory" design).

Every swap_interval draws (via NUTSCore.nuts_sample!'s callback hook), lane temperatures are proposed to swap with their current adjacent-in-rank neighbor (NUTSCore.pt_swap!, even/odd schedule) using each lane's freshly re-evaluated raw log-likelihood (_raw_loglikelihood! – NOT nuts_draw!'s own tempered logp, see that function's docstring for why). swap_interval=1 proposes a swap after every single draw; larger values let each temperature's chain mix locally between swap attempts, the usual PT tradeoff.

Step-size adaptation (dual averaging) is already PER-WALKER in NUTSCore (unrelated to this feature), which is exactly what different-temperature lanes need anyway: a hot (small-beta, flattened) lane's well-adapted step size can be very different from the cold lane's.

Returns (state, pt, cold_chain): state.positions/state.logp are left as NUTSCore.nuts_sample! leaves them (every lane's FINAL draw, at whatever temperature that lane ended up holding – NOT necessarily beta=1, since swaps permute temperature labels across lanes over the run). pt::NUTSCore.PTLadderState is the final ladder/lane bookkeeping (pt.naccept ./ pt.nattempt, one entry per adjacent pair indexed by its lower rank, gives each pair's running swap acceptance rate – the standard PT tuning diagnostic). cold_chain is a (nparams, cfg.nsteps) array: the beta=1 chain's position after EVERY draw, assembled by following pt.lane_of_rank[1] (whichever lane currently holds beta=1) at each step – THIS, not any single fixed lane of state.positions, is the array a caller should treat as posterior samples from the target distribution.

pt_backend (default KernelAbstractions.CPU()): backend PTLadderState's betas/ lane_of_rank/rank_of_lane are allocated on – pass CUDABackend() (after using CUDA) to run the swap kernel itself on-device; independent of whatever backend state.positions lives on (_raw_loglikelihood!/gw_logp_and_grad already dispatch their own kernel backend from positions/data, same as batched_nuts!). Not validated on CUDA hardware; see NUTSCore's PT section comment.

adapt_mass (default false): adapt a diagonal mass matrix during warmup, attached to the temperature RANK (via pt.rank_of_lane), not to the lane – lanes exchange beta labels on a swap, so a per-lane metric would go stale after every accepted swap. Each rank learns its own scales (hot ranks legitimately broader). See NUTSCore.nuts_sample!'s metric_rank. Step sizes remain per-lane (they are dual-averaged during warmup only and are not rank-attached).

GravitationalWaveBayes.AnalyticInit.analytic_beta_min — Method
analytic_beta_min(snr2, nparams; floor=1e-3) -> beta_min

First-pass heuristic PT ladder floor: the tempered log-likelihood curvature at inverse temperature beta scales as beta * snr2, so beta_min = nparams / snr2 puts the HOTTEST rung's curvature at roughly O(nparams) – flat enough that it explores close to the prior (the standard PT design goal for the hottest chain) without being so flat it wastes the whole ladder on rungs indistinguishable from the prior. Clamped to [floor, 1]. This is a heuristic starting point, not a validated optimum – unlike analytic_reference_metric/informed_initial_positions (directly justified by real-data dense-metric runs), this needs real-data PT swap-acceptance validation before being trusted on a production ladder.

GravitationalWaveBayes.AnalyticInit.analytic_snr2 — Method
analytic_snr2(data::LikelihoodData, freqs, ref_point; model=IMRPhenomXHM()) -> snr2

Optimal (noise-free) matched-filter SNR^2 of model at ref_point against data's PSD: snr2 = <h,h> = 4 * Re(sum(|h(f)|^2 / psd(f))) * df. Computed WITHOUT any model-specific amplitude/phase machinery (several models, including IMRPhenomXHM, have no single-valued Ampl/Phi to call directly – see RelativeBinning.jl's own _bin_placement_model comment for the same issue) by reusing the generic likelihood evaluation against a COPY of data with strain zeroed: with dd=0 and dh=0, logL(zero_strain_data, ref) = -0.5*hh, so hh = -2*logL. GravitationalWaveBayes.AnalyticInit.informed_initial_positions — Method
informed_initial_positions(::Type{T}, nwalkers, metric, ref_point; rng, nrows=11, scale=1.0)

Disperse nwalkers starting positions around ref_point along metric's actual correlated directions (ref_point .+ scale .* metric.L * randn(nparams), i.e. scale standard deviations of the ESTIMATED posterior shape in a random direction) instead of _gw150914_initial_positions's independent per-parameter jitter. Motivated by a real-data finding: independent per-parameter dispersion is blind to the mc/t_c/phase ridge and can land a walker in a secondary mode that a correlation-aware draw would have avoided by staying on-ridge.

Periodic rows (phase/ra/psi) wrap via mod, box rows clamp into [lo, hi], exactly mirroring _gw150914_initial_positions's own post-processing – a correlated draw can push a coordinate out of its physical bounds just as easily as independent jitter can.

metric === nothing (the reference Hessian was unusable, see analytic_reference_metric) falls back to _gw150914_initial_positions's plain independent-jitter dispersion at dispersion=0.02, rather than erroring – an informed start is a convenience, not a correctness requirement.
