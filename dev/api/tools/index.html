Convergence diagnostics

GravitationalWaveBayes.Diagnostics.ParamDiagnostic — Type
ParamDiagnostic{T}

Per-parameter convergence/mixing summary produced by chain_diagnostics.

  • name: parameter label (from the caller's names argument, or "param$i").
  • rhat: split-Rhat (split_rhat); target <~ 1.01-1.1 for a trustworthy run.
  • ess: effective sample size pooled over all walkers (ess_multichain: the between-walker variance counts, so walkers stuck near their own values – e.g. a few draws from a resampled SMC population – are not counted as independent samples, which a sum of per-walker ess_geyer would do).
  • mean/std: pooled posterior mean/std across all post-warmup draws of all walkers.
  • walker_mean_range/walker_std_range: (min, max) of each walker's OWN mean/std – a large spread here (as opposed to rhat alone) is a direct, easy-to-read symptom of walkers stuck in different modes (this is exactly what caught the GW190412 two-good/fourteen-stuck split).

GravitationalWaveBayes.Diagnostics.chain_diagnostics — Method
chain_diagnostics(chain::AbstractArray{T,3}; warmup::Int=0, names=nothing) -> Vector{ParamDiagnostic{T}}

Compute per-parameter ParamDiagnostics from a recorded NUTS chain, chain[p, w, t] = parameter p's value for walker w at recorded step t – exactly the layout NUTSCore.nuts_sample! returns as its chain field when called with record=true, and the layout the real GW190412 result file (gw190412_xhm_result.jls) stores.

warmup: number of leading steps (dual-averaging adaptation window) to discard before computing diagnostics – pass cfg.nwarmup/nuts_cfg.nwarmup from the run that produced chain. Must leave at least 4 post-warmup draws (see split_rhat).

names: optional Vector{String}/Vector{Symbol} of length size(chain, 1) for readable output (e.g. ["mc", "q", "chi1", ...] for this codebase's 11/15-row sampled convention documented in BatchedNUTS.jl); defaults to "param1", "param2", ... .

GravitationalWaveBayes.Diagnostics.ess_geyer — Method
ess_geyer(x::AbstractVector{T}) where {T<:Real} -> T

Effective sample size of one (single-chain) draw sequence x, via Geyer's initial monotone sequence estimator (Geyer, C.J. 1992, "Practical Markov Chain Monte Carlo", Statistical Science 7(4):473-483, Section 3.3; the same construction underlies Stan's/bayesplot's ESS). Consecutive lag-autocorrelation pairs rho[2m] + rho[2m+1] are summed while the running pair-sum stays positive AND the sequence of pair-sums stays non-increasing (each pair-sum is clipped down to the previous one if it would otherwise rise, per Geyer's monotonicity correction – this rejects noisy upward blips in the empirical autocorrelation at large lag rather than including them, which is what makes this more robust than a naive single-lag cutoff like |rho| < threshold). The integrated autocorrelation time is tau = -1 + 2*sum(clipped pair-sums), and ess = n / tau.

Returns T(NaN) for a constant sequence (zero sample variance – autocorrelation is undefined). Returns T(length(x)) (i.e. tau floored at 1) if the very first pair-sum is already non-positive, matching the standard convention that a sequence with no detectable positive autocorrelation is treated as (at best) as informative as i.i.d. draws, not MORE informative.

GravitationalWaveBayes.Diagnostics.ess_multichain — Method
ess_multichain(draws::AbstractMatrix{T}) where {T<:Real} -> T

Effective sample size of draws ((ndraws, nchains)) pooled over all chains: n m / tau with the lag-t autocorrelation measured about the POOLED mean and variance, rho(t) = mean_{i,j} (x[i,j] - mu)(x[i+t,j] - mu) / s^2, truncated by Geyer's initial monotone sequence as in ess_geyer. The between-chain variance therefore counts: walkers that each sit near their own value (particles stuck in one of several modes, too few draws to leave a resampled duplicate's neighbourhood) count as about one sample each, where a sum of per-chain ESS counts every draw. It assumes the chains start in the target (the walkers of a stationary run, an SMC population at beta = 1); a drifting start shows up as extra correlation, i.e. a conservative ESS. Unlike the per-chain-mean form (Vehtari et al. 2021, eq. 10) it is unbiased for a few draws per chain: centring each 10-draw chain on its own mean makes the lag-1 autocovariance negative (-s^2 / n) and puts i.i.d. draws at ~1.6 n m.

GravitationalWaveBayes.Diagnostics.split_rhat — Method
split_rhat(draws::AbstractMatrix{T}) where {T<:Real} -> T

Classic split-Rhat (potential scale reduction factor) for one parameter, draws[t, w] = the t-th post-warmup draw of walker w (size (ndraws, nwalkers)).

Method (Gelman & Rubin 1992; Gelman, Carlin, Stern, Dunson, Vehtari & Rubin, Bayesian Data Analysis, 3rd ed., Section 11.4): each walker's chain is split in half, giving 2*nwalkers half-length "chains" of length n = ndraws ÷ 2. Between-chain variance B and within-chain variance W are combined into var_hat = ((n-1)/n)*W + B/n, an estimate of the marginal posterior variance that is unbiased if the chains have converged and an overestimate otherwise (each individual chain, having not yet explored the full posterior, underestimates W relative to the true variance while B picks up any persistent inter-chain offset); Rhat = sqrt(var_hat / W) is therefore >= 1 in expectation, converging to 1 as the chains mix. Splitting each chain in half (rather than using whole chains directly) additionally makes Rhat sensitive to non-stationarity within a single chain (a chain that drifts over its own length looks like two disagreeing half-chains), which is why this is the version used here and in Stan, not the original 1992 whole-chain-only statistic.

This is the classical statistic, not the rank-normalized/folded Rhat of Vehtari et al. (2021, Bayesian Analysis, "Rank-normalization, folding, and localization: An improved Rhat for assessing convergence of MCMC") – that improvement (more robust to heavy tails / multimodality in the per-chain marginal, and adds a separate check for scale, not just location) is a reasonable future upgrade but out of scope here: the classical statistic is exactly what already caught the real GW190412 non-convergence (values of 2.5-5.5, an order of magnitude past the ~1.01-1.1 target) this module exists to make routine, so there is no evidence it is too weak for this codebase's actual failure modes yet.

Returns one(T) for a degenerate all-identical input (W == B == 0); returns T(Inf) if the within-chain variance is exactly zero while the between-chain variance is not (chains agree internally but disagree with each other – the worst-case non-convergence signature). Throws ArgumentError if ndraws < 4 (need at least 2 draws per half-chain per walker).

GravitationalWaveBayes.Cosmology.source_frame_log_weights — Method
source_frame_log_weights(dL_mpc, lo_mpc, hi_mpc; cosmology = PLANCK15_LAL) -> Vector{Float64}

log p_sf(d_L) - log p_vol(d_L) with BOTH priors normalized on [lo, hi] (pvol = 3 dL^2 / (hi^3 - lo^3)): importance weights from a run under the dL^2 prior to bilby's UniformSourceFrame(lo, hi). Their posterior mean is Zsf / Zvol, so `logZsf = logZ_vol + log(mean(exp.(logw)))`.

GravitationalWaveBayes.Cosmology.source_frame_prior_weights — Method
source_frame_prior_weights(dL_mpc; cosmology = PLANCK15_LAL) -> Vector{Float64}

Importance weights (normalized to max 1) taking samples drawn under a d_L^2 prior to the uniform-rate-in-source-frame prior p(dL) ∝ [dVc/dz / (1 + z)] / (ddL/dz), dVc/dz = 4π Dc^2 DH / E(z): w = p(dL) / dL^2. Both priors share the same d_L bounds (the reweighting cannot extend the support).

GravitationalWaveBayes.GPU.compatible_array — Method
compatible_array(T::Type, dims::NTuple{N,Int}) -> AbstractArray{T,N}

Allocate an uninitialized T-element array of shape dims on whichever device this session is configured for – the allocating analogue of to_device for code that needs a fresh array rather than a device copy of an existing one (e.g. a kernel's output buffer). The base (CPU-only) behavior is Array{T}(undef, dims); loading CUDA.jl reassigns the allocator this function calls to CUDA.functional() ? CuArray{T}(undef, dims) : Array{T}(undef, dims) (see GravitationalWaveBayesCUDAExt's __init__) – callers never need to branch on which backend is active.
